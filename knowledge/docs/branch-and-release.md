## 分支模型

| 分支 | 用途 | 生命周期 |
| --- | --- | --- |
| main | 随时可发布 | 长期 |
| feature/功能名 | 单功能开发 | 合并后删除 |
| hotfix/问题名 | 线上紧急修复 | 合并后删除 |

统一使用 `feature/姓名-功能名` 的命名，例如 `feature/zhangsan-learn-ask`。

## 日常流程

1. 从最新的 main 切出功能分支。
2. 小步提交，每完成一个可验证的点就提交一次。
3. 推送分支前先拉一次 main 并合并，解决冲突后再推。
4. 提交合并申请，说明改了什么、怎么验证的。
5. 合并后删除本地与远程的功能分支。

## 合并前必做

1. 本地跑一遍完整流程，把验证方式写在合并说明里。
2. 数据库脚本能重复执行，不依赖手工删表。
3. 配置文件里的新配置项要有默认值，缺省时不影响启动。

## 禁止事项

1. 直接往 main 推代码。
2. 用强制推送覆盖别人已经拉过的分支。
3. 把本地配置文件、日志、临时目录提交上去。

## 出问题怎么办

线上出问题先回滚到上一个可用版本，再按 hotfix 流程修复，
不要在 main 上边改边等。回滚记录要写进当天的工作记录。
