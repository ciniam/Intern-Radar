## 排查顺序

1. 工具是否注册成功。注册用的是回调数组，不是带注解的普通对象，
   两者混淆会在调用时报找不到注解方法的错误。
2. 模型是否被允许调用工具。系统提示词里必须明确要求先检索再作答。
3. 循环是否能正常收尾。收尾条件是某一轮不再发起工具调用，
   因此下一步提示词里要写清「信息足够就直接给出最终回答」。
4. 步数是否够。步数太小模型还没读完文档就被强制结束，步数太大容易空转烧 token。
5. 上下文是否爆掉。工具返回的正文必须截断，否则一篇长文档就能把上下文塞满。

## 观察点

| 观察项 | 期望 |
| --- | --- |
| 每轮日志 | 能看到「选择了几个工具」以及工具名与参数 |
| 工具返回 | 有明确内容，不是空字符串或异常堆栈 |
| 结束原因 | 正常收尾，而不是达到最大步数 |
| 用量 | 输入与输出 token 都有记录，便于评估成本 |

## 常见错误做法

1. 用普通工具对象去注册回调，导致工具永远不生效。
2. 把工具返回的原始正文不加截断直接塞回上下文。
3. 提示词里没有收尾条件，循环一直追加下一步提示词空转十几轮。
4. 只记录总耗时，不记录 token 与工具调用次数，出问题无从下手。

## 评测口径

检索命中率按「有命中的检索次数除以总检索次数」统计，
同时记录读取篇数与读取字符数，用来判断检索是不是又准又省。
