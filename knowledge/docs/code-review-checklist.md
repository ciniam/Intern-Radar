## 提测前自查

1. 编译通过，且没有新增告警。
2. 新增接口能用接口文档页面直接调通一次。
3. 异常分支有明确日志，日志里带上关键业务标识。
4. 没有把密钥、账号、内网地址写进代码或提交到版本库。
5. 数据库改动都用 IF NOT EXISTS 或可重复执行的写法。

## 评审关注点

| 关注点 | 具体要求 |
| --- | --- |
| 边界条件 | 空集合、null、超长文本、时间跨天都要有处理 |
| 幂等 | 定时任务与采集类逻辑必须有去重键，重复执行不产生重复数据 |
| 事务 | 一次写入多张表时才加事务，外部调用不要放在事务里 |
| 外部依赖 | 第三方接口失败要有降级路径，不能把整个流程拖死 |
| 命名 | 方法名体现动作，布尔字段避免用否定词 |

## 不接受的写法

1. 吞掉异常只打印一行日志，不给出上下文。
2. 在循环里查数据库，且没有分页或批量查询。
3. 硬编码第三方地址与凭证。
4. 为了绕过某个报错直接注释掉校验逻辑，且没有留下原因。

## 评审礼仪

1. 每条意见给出理由，不要只说「这样不好」。
2. 意见分「必须改」和「建议改」两档，避免阻塞无关紧要的细节。
3. 作者不接受意见时要给出依据，争议超过两轮就拉上导师当面十分钟。
