## 四步定位法

1. 接口是否可达。先访问健康检查地址，确认服务在跑、端口与上下文路径没写错。
2. 参数是否正确。看请求参数名与类型，日期参数注意格式。
3. 数据是否落库。直接查表确认采集结果，不要把「接口返回成功」当成「数据已入库」。
4. 外部依赖是否可用。模型、内部系统、协作平台任意一个不通都会表现为接口报错。

## 高频问题对照

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 新接口全部 404 | 启动类扫描范围不含新包，控制器没注册 | 显式声明扫描包 |
| 模型调用返回 401 | 密钥没填或失效 | 核对本地配置文件里的密钥 |
| 请求头非法字符 | 密钥或配置项里含中文 | 改成 ASCII 占位符或真实值 |
| 接口 500 但日志没细节 | 异常被吞掉 | 补上带上下文的日志再复现 |
| 定时任务重复执行 | 没有幂等键 | 用唯一键抢占，同一人同一任务同一天只跑一次 |
| 采集到零条但没有报错 | 外部系统返回了登录页或权限拒绝页 | 识别特征并抛出明确异常 |

## 排查纪律

1. 先复现，再定位，最后才改代码。没有复现路径的修改一律不做。
2. 改动前先备份当前可用的配置与数据。
3. 每次只改一个变量，改完立刻验证。
4. 把现象、原因、处置记进工作记录，否则下次还会踩。

## 需要立刻停下来找导师的情况

1. 涉及删除数据、重置环境、强制推送的操作。
2. 需要连续重试登录类接口，有锁号风险。
3. 排查超过两小时仍无进展。
